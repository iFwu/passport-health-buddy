# 平板支撑自由计时器

开机进入专用 `PLANK` 页面，自由开始、随时结束。记录撑了多久，没有目标时长、排名或最低达标时间；短时也照常保存。不需要网络，不判断运动姿势，也不提供医疗或训练指导。

先看[三分钟中文小课](learning/lessons/0001-firmware-and-records.html)，或直接按下面使用。

## 三键操作

| 当前状态 | OK | UP | DOWN |
| --- | --- | --- | --- |
| 等待开始 | 开始约 4 秒准备 | 有可补存记录时重试，否则切换提示音 | 查看历史 |
| 准备中 | 取消准备 | 取消准备 | 取消准备 |
| 正在计时 | 立即结束并保存 | 立即结束并保存 | 立即结束并保存 |
| 保存处理中 | 等待 | 等待 | 等待 |
| 已保存结果 | 下一次准备 | 切换提示音 | 查看历史 |
| 保存失败，启动读取正常 | 下一次准备 | 重试保存 | 查看历史 |
| 未保存结果，启动读取异常 | 下一次准备 | 切换提示音 | 查看本次开机的 RAM 历史 |
| 历史 | 返回等待开始 | 较新记录 | 较旧记录 |

准备阶段用于摆好设备，准备倒计时不计入时长。进入计时后，任何键按下立即结束，不需要长按或等松手。保存处理中忽略按键，避免把一次结束误当成下一次开始。

内部以毫秒记录时长。主计时页由 LVGL 直接绘制粗笔画、斜切端部的七段数字，只显示点亮的段，不绘制未点亮的底纹，也不嵌入数字字体。64 px 大秒数与 32 px 的两位小数同行、底部对齐，例如 `59.99`。不足一分钟只显示秒和小数；满一分钟后，右上方另显示 28 px 累计分钟和较小的 `MIN` 单位（如 `1 MIN`）。分钟和秒不补前导零，小数始终保留两位，各数位固定宽度和位置。浅色读数区配深色数字，底部操作区配深色底和白字，提高小屏阅读对比度。100 小时及以上显示 `99h+`，仍保存真实时长。历史页不足一小时显示 `MM:SS.xx`，一小时至不足 100 小时显示 `HH:MM:SS`。小数显示步长为 0.01 秒（10 毫秒），不表示屏幕每 10 毫秒重绘，也不是仪器校准的准确度承诺；主循环约每 20 毫秒刷新一次，显示可以跳过中间值。历史保留最近 20 条，由新到旧浏览，满 20 条后结束新一次计时会挤出 RAM 历史中最旧的一条，包括尚未保存的旧记录。

## 提示音

默认开启。按下开始后，屏幕依次显示 `4、3、2、1`，每个数字停留一秒并同步播放一次 1000 Hz、120 ms 的同音短提示，共四声。最后显示 `0`，同时播放一个 2000 Hz、350 ms 的高音长声并开始计时，避免与双声结束提示混淆。这个节奏借用 F1 逐灯点亮、全部熄灭才起步的结构，不使用容易听成折返的连续升调。真实赛事在全部红灯点亮后会有不可预测的熄灯延迟；训练版仍使用固定准备节奏，避免在摆姿势时制造反应压力。真实发车信号是灯光，本应用的声音是无须盯屏的适配，并非赛事信号复刻。

计时中每 10 秒提示一次，10 秒是一声、30 秒是两声、整分钟是三声，用节奏区分阶段；结束播放两声。没有背景音乐。UP 的声音开关只影响本次开机，重启恢复默认开启；有可补存记录时，UP 优先用于重试。开始和结束音不会因等待超过 500 ms 被丢弃；过期周期提示会跳过，队列满或播放失败会显示声音不可用。提示音用于提醒计时状态，不要求继续坚持。

当前采用方波合成：16 kHz、16 bit、单声道、峰值 6000、驱动音量 80，播放按最多 512 个采样分块写入并保持相位。四次准备提示均为 1000 Hz、120 ms；进入计时时播放一个 2000 Hz、350 ms 的长音。10 秒提示为 1000 Hz 单声，30 秒为 800 Hz 双声，整分钟为 1200 Hz 三声；结束为 1000 Hz 双长声。脉冲之间写入静音以定义音间节奏。准备和周期提示过期 500 ms 后跳过；取消准备、开始、结束或关闭声音会使旧提示失效，播放器在下一次分块写入前检查，已经进入硬件缓冲的数据仍可能有短暂尾音。这些是程序参数，不是实际声压测量。新开始提示仍需真机试听，已确认的可听性覆盖 1 kHz 方波。串口的 `Audio cue` 报告实际写入采样数，不代表扬声器可听性已验证。

发车结构参考：[FIA 场地赛静止发车灯光建议](https://argent.fia.com/web/fia-public.nsf/1330F0769A59327AC125736200478FB9/$FILE/03__Recommended_light_signals.pdf)与 [F1 发车流程说明](https://www.formula1-dictionary.net/f1-race-start-sequence/)。

音频由独立任务播放，不等待音频完成才处理计时；声音不可用时屏幕会提示。听不到声音时请依据屏幕确认状态，设备实际音量与提示时机仍需真机验证。

## 什么才算保存

- 正在计时的本次状态在 RAM 中，掉电就丢失，不会自动补成历史。
- 按结束后写入 Flash 中的 NVS，提交成功才显示已保存。写入过程中掉电，本次记录可能丢失；之前成功提交的记录正常应保留，但这不是对 Flash 损坏的保证。
- 启动读取正常、结束后保存失败时，结果页显示“未保存 仅临时保留”。保持供电，按上键重试。也可按确定开始下一次；未保存结果留在最近 20 条 RAM 历史中，下次成功保存时整份历史一起补存。历史中仍会区分尚未保存的记录，看到记录不等于已经落盘。
- DOWN 打开历史，OK 返回等待开始页；只要还有可补存记录，上键仍可直接重试，无需再计时一次。在重试成功之前，掉电会丢失 RAM 中所有尚未保存的记录；继续超过 20 条也会挤出最旧记录。
- 启动时存储初始化、读取或格式检查失败，则本次开机禁写，保留 Flash 原有内容。仍可自由计时，结果只保存在本次开机的 RAM 历史，UP 仍用于切换声音，不会重试写入。原有历史此时不能当作已成功加载。
- 写入空间不足或其他错误不自动擦除 NVS；数据损坏、格式版本不支持时不覆盖不可识别的历史。请保留错误信息供排查，不用整片擦除解决。
- 记录没有日期和身体个人数据，只保存时长与新旧顺序。没有可信时钟就不把记录标成“今天”。声音开关不属于持久记录。

开发实现使用 NVS namespace `plank`、key `history_v1` 的带版本单个 blob 保存最近记录。结束时先加入 RAM 历史；成功提交整份历史后才推进已保存标记，单纯重试不会新增一条计时记录。

“未保存”表示应用没有确认提交成功；异常中断后 NVS 也可能恢复出完整的新记录，应以重启后实际读到的历史为准。

## 更新程序与恢复

已有秒表应用可以计时；本应用新增专用开机界面、三键操作与持久记录。源码经 ESP-IDF 5.5.3 编译为 `.bin`，安装进 Flash 后，bootloader 启动应用，设备即可离线运行。复用 BSP，不需要换硬件或重写驱动；未假设设备目前安装了哪个应用。

安装前需要核对实际产物、分区和目标设备，再单独确认烧录。主应用上限 3 MB；设备身份 `cardid` 位于 `0x356000`，permanent Recovery 位于 `0x700000`，不能擦除或覆盖。仓库保留开机持续按 UP 五秒进入 Recovery 的 hook；设备当前 Recovery 是否完好尚未验证。

不要运行 `erase-flash`，也不要把任意 `.bin` 当成可写到 `0x0` 的完整镜像。app-only、merged image 与分段安装的用途见[兼容合同](development/engineering/ble-recovery-compatibility.zh_CN.md)。本手册不自动授权安装、擦除或设备重启。

## 真机验收

本地完整检查运行 `./tools/validate.sh`：仓库检查、纯计时与存储 host tests、固件构建与分区验证，以及真实 LVGL 的 240×320 布局和像素检查。已有构建依赖时，可以单独运行 `bash tools/test-plank-ui.sh`，预览输出位于 `build/plank-ui/previews/`。预览来自桌面渲染，不是真机截图。

macOS 上该脚本还会生成 PNG 和 `build/plank-ui/previews/index.html`。直接打开 HTML 即可查看关键状态、试听准备及各级音效，不需要 USB 或 ESP-IDF 构建。页面展示真实 LVGL 渲染的静态截图；WAV 与固件共用 `main/plank_audio.c` 的 PCM 合成器，由 host 测试导出，电脑播放不复现 ES8311 的音量曲线和设备扬声器响应。预览更新只需增量编译 host 程序。模板位于 `tools/plank-preview.html`。

若内嵌浏览器通过自定义文件协议打开时音频报错，可在仓库根目录运行下面的本地预览服务，再打开 `http://127.0.0.1:8765/`。端口被其他服务占用时换一个空闲端口。更新预览后刷新网页即可，不需要烧录。

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory build/plank-ui/previews
```

构建成功只证明工具链检查通过。安装经单独确认后，还需验证：准备中三个键分别能取消；计时中三个键分别即时结束；不足一秒仍保存；连续多次记录与满 20 条后的顺序；已保存记录断电重启后仍可见；声音开关与可听性；屏幕文字无截断。掉电和存储错误场景优先通过 host tests 与受控测试验证，不对带身份数据的设备随意制造 Flash 故障。

未实测前，不把按键响应、音量、计时准确度或 Recovery 状态描述为已通过。学习目标与官方资料见[教学目录](learning/README.md)。
